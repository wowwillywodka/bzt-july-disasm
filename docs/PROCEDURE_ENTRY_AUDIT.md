# Аудит временных имён точек входа

Статически проверена 101 точка, ранее учитывавшаяся как временно именованная. Имена и модули заменены по инструкциям и непосредственным переходам; исходники и `metadata/layout.json` согласованы; в рабочей копии также обновлены каталог функций и таблица символов. После выделения 18 настоящих callback число содержательно названных размеченных точек составило 963; последующий [аудит графа входов](ENTRY_PROVENANCE.md) добавил 17 пропущенных целей прямого вызова, итого **980/980**. Это не означает, что в ROM осталось ноль неизвестных инструкций, ресурсов, вложенных входов или недостижимых ветвей. Некоторые точки в этой метрике — продолжения соседней процедуры.

## Границы, которые нельзя считать отдельными процедурами

| Адрес | Роль и необходимый контекст |
| --- | --- |
| `$00A900` | Продолжение проверки кэша видимых граней. Первая инструкция — `BEQ` на основании флагов, установленных предыдущим блоком. |
| `$00A962` | Альтернативная ориентация той же грани; использует регистры и `MOVEM`-кадр из `$00A900`. |
| `$00ABA2` | Две половины открывающейся стены. Вход из `RenderOpeningWallAlongX` при величине открытия не `$80`. |
| `$00FD9A`, `$00FE60` | Развёрнутый программный блиттер столбца спрайта. Таблица `SpriteColumnEntryPointers` прыгает в разные **внутренние** позиции цикла; граница `$00FE60` выбрана для разделения исходника, а не по `RTS`. Источник пиксельных индексов `A2`, таблица перекодировки `A1`, таблица цветов `A3`, адрес назначения `A0`; нулевой перекодированный индекс пропускает запись. |
| `$01E2D2` | Ветвь из `SteerEnemyMotionAtNearbyWall`: ограничивает дробную Y-координату; рядом расположены аналогичная X-ветвь и переход к `ActorExitCallback`. |
| `$02267E` | Продолжение `StepPaletteFade`: берёт регистры и счётчик `DBRA` у предшествующего блока. |

У `UpdatePlayerInputMovementAndCollision` `$00E30C` большой исходный раздел длиной `$8D4` байта: имя описывает общий путь кадра. Его устойчивые внутренние фазы названы, а условия и зависимости регистров вынесены в [схему движения](PLAYER_MOVEMENT_FLOW.md). Внутренние фазы не внесены в каталог как самостоятельные процедуры.

## Пакеты состояний врагов

`SendBloodBodyState`, `SendStananState`, `SendGunnerState`, `SendGreyDummyState`, `SendGreenDummyState`, `SendWhiteDummyState`, `SendBeatressState`, `SendBlueDummyState` и `SendDogState` заполняют `rSharedScratchBuffer`. Небольшие входы `$01F06C..$01F7E2` ставят разные `D0/D2`, затем переходят в `QueueLinkCommand`. **Проверенный результат:** `QueueLinkCommand` перезаписывает `D0` и не читает `D2`, поэтому эти значения не различают пакеты на линии. `D2` при этом сохраняется после возврата, так что его значение ещё может быть заметно вызывающему коду. Имена `VariantA/B/C` обозначают ветку исходного кода, а не отдельный тип сетевой команды или анимации.

После безусловного `JMP` начинались два отдельных callback: `Draw*BaseFrame` и `Draw*StateParityFrame`. Для девяти врагов они физически отделены от отправки в самостоятельные исходные блоки `actors`; короткие отправители перенесены в `link`. Адреса callback перечислены в `ActorRemoteUpdateHandlers`, поэтому это реальные входы, а не продолжение отправки. Для будущего изменения формата пакета смотреть `LinkCommandSizes`, отправитель и обработчик приёма; для замены спрайта — именно `Draw*` и банк актёра.

## Остальные нетривиальные контракты

| Вход | Проверенное действие / ограничение |
| --- | --- |
| `$0025C4`, `$002606`, `$00267E` | Генерация случайного аппаратного спрайта сохранённого экранного эффекта: координаты и атрибуты вычисляются по углу игрока, затем запись через `AppendHardwareSprite`. `$002606` также содержит ветви вызывающего кода после `RTS`. |
| `$00274E`, `$00279E`, `$002800` | Проверка типов клетки `$27/$28`, постановка и кадровый тик маркера сохранённого эффекта. Путь зависит от RAM-флагов эффекта; это не универсальный HUD-таймер. |
| `$00D166`, `$00D1A2`, `$008DF6` | Обновление пер-клеточного render-state; второй вход увеличивает счётчик цели, если побочные эффекты разрешены. Обработчик `$008DF6` передаёт указатель клетки именно во второй вход и возвращает `D3=1`; прежнее название про профиль высоты было неверным. |
| `$01D130`, `$01D880`, `$097964` | Выходы актёра с записью клетки карты и удалением; `$01D130` выбирает профиль трупа, `$097964` явно пишет профиль `$8C`. |
| `$01E4FA` | Поиск ближайшего актёра по всем битам маски `D5`, на том же этаже; нулевой `A0` задаёт начало от игрока, ненулевой допускает самого игрока как кандидата. `A1=-1` при отсутствии. |
| `$020534` | Обработчик link-команды `$19` при роли получателя 2. Сравнивает один `ActorExitCallback` сначала с `$1D880`, затем с `$1D25A` и попадает в ветвь удаления только при обоих равенствах. Условие недостижимо для обычного значения указателя; логика прототипа сохранена без исправления. Локального прямого отправителя команды `$19` не найдено; одноимённый spawn kind — поле внутри команды `$04`. |
| `$020570` | Обработчик link-команды `$16`: очищает флаг экранного эффекта и уменьшает бюджет, если он не ноль. Адреса `$020580/$020584/$02058C/$020594` выделены в отдельные блоки команд disconnect, паузы и выдачи предмета. |

Другие подтверждённые контракты записаны в [link](LINK_PROCEDURE_CONTRACTS.md) и [видео/UI](VIDEO_UI_PROCEDURE_CONTRACTS.md). Разделы ROM и расположение исходников перечислены в [карте разделов](../metadata/layout.json). Этот аудит статический; динамическая проверка редких ветвей и link-сеанса ещё не заявлена.
