# Двойные входы на границах исходных файлов

В июльском BZT 12 физических участков начинаются с инструкции, в которую можно войти вызовом (`BSR/JSR`, в том числе косвенным) **и** провалиться из предыдущего участка. Граница файла здесь не всегда граница процедуры. Этот список получен из декодированных инструкций и областей целей косвенных переходов; `make audit-entry-provenance` проверяет адрес предшественника, тип входа, имя и контракт в каталоге. Косвенная область целей — верхняя оценка, а не подтверждение исполнения каждой пары «сайт → адрес».

| Вход | Два контекста | Контракт прямого входа / эффект |
| --- | --- | --- |
| `$008DDE` `BuildEmptyCellProfile` | Таблица обработчиков клеток вызывает адрес напрямую; `$008DD8` сначала вызывает `QueueProjectedWorldObject` | Установить `D3.W=0`, возврат. Прямой вход не ставит объект в очередь. В `VisibleCellHandlers` есть оба адреса. |
| `$0097A8` `SpawnActorsInSevenBySevenWindow` | Продолжение проверки не-соседнего сдвига окна `$0097A4`; прямой вызов из обработки взрыва `$01E434` | `A0` задаёт исходную клетку, `A4` — селекторы, `A5` — LUT типов. Сканирование 7×7, но границы и счётчики координат берутся из **глобальных координат игрока** даже при вызове от взрыва. Взрыв временно переключает текущий этаж. |
| `$00DF9E` `QueueSoundEventLinkCommand` | `$00DF9C` перед этим вызывает локальный звуковой диспетчер; `$00DF7E` вызывает только сетевой хвост | `D0.B` — ID события; поставить link-команду `$08`. Сам вход звук не воспроизводит. Сохраняет `D0/D1/A0/A1` через стек. |
| `$01173A` `UploadInventorySlotIconsToVram` | Продолжение сброса инвентаря после `$011738`; отдельные вызовы из UI | Ждать окончания фаз передачи, заново загрузить `A0=rInventorySlots`, задать VDP-адрес и вывести четыре иконки. Входной `A0` не используется. |
| `$01175E` `UploadInventorySlotIconToVram` | `$01175C` предварительно сдвигает `A0` на четыре байта; прямые вызовы указывают нужный слот сами | `A0` — текущий слот; поток записи VDP уже позиционирован вызывающим кодом. Выводит графику/счётчик одного слота, меняет рабочие регистры. |
| `$01BEBC` `ActorNoOp` | `UpdateActors` доходит сюда после `DBRA`; таблицы и поля callback могут указывать сюда | Только `RTS`. Это одновременно конец цикла и намеренная пустая функция обратного вызова. Перечень косвенных сайтов в графе не означает, что все они фактически выбирают этот адрес. |
| `$01DB3C` `RemoveHitParticle` | Выпадение carry из `$01DB3A` либо exit callback актёра | `A0` — удаляемый актёр. Если `rHitParticleCount` ненулевой, уменьшить его; затем перейти в `RemoveActorAndSendLink`. Повторное уменьшение при нуле не происходит. |
| `$07A8D4` `WriteGemsCommandByte` | `$07A8D0` предварительно маскирует `D1.B` после записи префикса `$FF`; 13 прямых вызовов пишут аргументы/команды | `A0=$A00036` — регистр индекса, `A1=$A01B40` — буфер Z80, `D1.W=0..63`, `D0.B` — байт. Запись в `A1[D1.W]`, индекс `+1 mod 64`, публикация нового индекса через `A0`. Подготовку указателей и шины делает `BeginGemsCommand`; этот вход сам её не делает. |
| `$07ACE8` `PlaySoundEvent` | `$07ACE4` сначала пишет `D0` в `rCurrentSoundSequenceId`; 16 прямых вызовов входят сразу в диспетчер | `D0` — код события. Прямой вход **не обновляет** сохранённый ID последовательности. |
| `$0974DC` `CountMapCellIndex` | `$0974DA` выставляет `D0=-1`, если тип клетки не найден; восемь прямых вызовов при загрузке геометрии подают конкретные индексы | Добавить число совпадений `D0.B` в `D4.W`, просматривая весь `$4000`-байтный `rEpisodeMapCells`. При `$FF` скан пропускается, `D4` остаётся без изменения. Скан охватывает и неочищенный хвост арены, а не только занятые карты. |
| `$09773A` `ExtractVisibleMapWindow` | `ShiftWorldRelativeCoordinates` продолжает сюда, в эпизоде 0 сначала восстанавливает `D2/D3` с собственного стека; прямые вызовы из переходов уровня не делают этого pop | `D4/D5` — начало видимого окна в клетках. Копирует 32×32 байта; шаг исходной строки берёт из текущей ширины этажа. Вход не требует чужого сохранённого кадра стека. |
| `$098AA6` `RotateVectorMinusQuarterTurn` | `$098AA2` предварительно вызывает этот же вход один раз, затем проваливается в него; отдельные вызовы делают один поворот | Меняет `D0.L` и `D1.L`, затем отрицает **только младшее слово** `D1`. Вход `$098AA2` даёт два четверть-поворота, `$098A9E` — три. |

Практический вывод для дальнейшего редактирования: нельзя переносить подготовку из предыдущего файла внутрь общего входа или подменять прямой вызов вызовом предыдущей обёртки. В частности это изменит link-звук, сохранённый ID трека, содержимое GEMS-кольца и содержимое стека при извлечении окна карты. Контракты описывают семантику данного ROM; безопасность новых вызовов после ромхака нужно проверять отдельно.
