# Владение рабочей RAM июля

Карта для июльского BZT (SHA-256 ROM
`8f0af150b642e1e190566a96d19732695164d926244764407560949cee02d8b0`).
Здесь **время жизни содержимого** отделено от физического диапазона: временный
буфер не становится свободным только потому, что сейчас идёт другая стадия
кадра. Важны также прерывание VBlank, отдельные меню и повторный вход в
обработчик. Все адреса ниже — RAM 68000, а не адреса VRAM.

| Область | Подтверждённый диапазон / размер | Владелец и момент записи | Последнее использование / срок жизни |
| --- | --- | --- | --- |
| `SpriteAttributeTable` | база `$FF0044`; следующий именованный буфер начинается `$FF0544`, **это не доказанная ёмкость SAT** | Сборка аппаратных спрайтов в игровом кадре и отдельных экранах; tail `$FF003E`, link `$FF0042` | `UploadSpriteTable`/конец `RunGameplayIteration` ставят DMA в VRAM `$B800`. Не занимать до фактического завершения передачи. |
| `VramDmaCommandQueue` | база `$FF0544`; граница ёмкости не доказана | `QueueVramDma` добавляет семь слов на команду, игровой код завершает очередь long `$FFFFFFFF` | `FlushDmaQueue` читает на VBlank и сбрасывает tail `$FF0036`. Буфер занят между постановкой и flush. |
| `StatusSoundScript` | `$FF088E..$FF08AD`, 32 байта | Загрузка сценария из статусного сообщения | Последующие VBlank отсчитывают шаги; содержимое нужно до окончания сценария. |
| `StatusMessageQueue` | `$FF08D0..$FF090F`, 16 long | `QueueStatusMessage` добавляет указатель | `UpdateStatusMessages` извлекает и сдвигает очередь. Содержимое переживает отдельные кадры. |
| `SharedScratchBuffer` | база `$FF1024`; следующий владелец `$FF104E`, физический промежуток 42 байта, **проверенная общая ёмкость не установлена** | Link-пакеты, звуковые и текстовые команды, UI и вызовы врагов перезаписывают один scratch | Только локальная передача следующему потребителю. Нельзя сохранять указатель или занимать «хвост» без аудита всех писателей. |
| `ProjectedWorldObjectQueue` | `$FF10E8..$FF11AF`, 20 × 10 байт | Сброс tail `$FF11B0` на входе `TraceAndDrawVisibleWorld` `$00C124`; проекция добавляет записи | Рендер потребляет записи в этом проходе. `$FF11B0` — уже отдельное поле. |
| `PlayerActorProxy` | `$FF11E2..$FF1239`, `$58` байт | `UpdateActors` `$01BE18..$01BE40` обновляет **часть** полей из игрока | Цель для актёрских обработчиков; не входит в список и пул. Остальные байты не получают полный reset здесь. |
| `ActorPool` | `$FF123A..$FF2839`, 64 × `$58` байт | `ResetActorPool` `$01BFCE` очищает всё при сбросе сцены; `AllocateActor` `$01C090` и загрузчики определений пишут только часть слота | Состояние актёров сохраняется на протяжении сцены. `RemoveActor` очищает flags/next, но остальные байты остаются при повторном выделении. |
| `ProjectedActorHeap` | `$FF2842..$FF2A41`, 64 × 8 байт | Рендер строит кучу проекций актёров | Рендер извлекает её в том же проходе; `$FF2A42` уже `RemoteHitCommandVariant`. Собственной проверки вместимости у вставки нет. |
| `PackedCellRenderState` | `$FF3D9E..$FF5D9D`, 8192 байт | `LoadEpisodeGeometry` `$09721C..$09722A` очищает packed-состояние; обработчики клеток изменяют его | Состояние сцены/эпизода, не временная память кадра. |
| `Episode1CellRecords` | `$FF5DA4..$FF5E93`, 30 × 8 байт | Записи механики клеток первого эпизода | Действуют в сцене; физическое соседство с поездом не расширяет таблицу. |
| `ActorMarkerRecords` | `$FF5ECA..$FF5F41`, 120 байт | Загрузчик копирует ровно `$78` байт `$09727C..$09728A` | Маркеры доступны обработчикам карты и актёров до следующей загрузки геометрии; `$FF5F42` — `WallOpeningPermit`. |
| `BytePairFlags/Left/Right` | `$FF5F44..$FF6243`, три массива по 256 байт | Распаковщики byte-pair строят словарь на каждый вызов | Временные данные **вызова распаковки**, который возможен и во время игры. Инициализация flags затрагивает 257-й байт — первый байт `Left`. |
| `SoftwareFrameBuffer` | `$FF624A..$FF8A49`, 10 240 байт | Растеризаторы стен/спрайтов и композиция фона формируют программный кадр | Содержимое необходимо до передачи изображения в VRAM; граница проверена отдельно. |
| `ScreenColumnDepthWords` | `$FF8A4A..$FF8B49`, 128 слов | `TraceAndDrawVisibleWorld` `$00C12C..$00C156` обнуляет; стены записывают глубину | Спрайты и композиция читают в текущем проходе. |
| `SceneBackgroundColumns` | `$FF8B4A..$FF8BE9`, 2 × 80 байт | Пересэмплируется при изменении вида/цветового режима | Кэш читается последующими проходами; **не** обнуляется каждый кадр. |
| `CellIndexByType` | `$FF8BEA..$FF8CE9`, 256 байт | `LoadEpisodeGeometry` `$0971FE..$097218` строит обратную таблицу | Индекс клеток текущего эпизода. |
| `TextureDefinitions` | `$FF8CEA..$FF9CE9`, 4096 байт | Загрузчик копирует банк; анимация и надпись этажа меняют отдельные записи | Текущий эпизод; это изменяемые определения, не read-only ROM-копия. |
| `TextureOrder` | `$FF9CEA..$FFA4E9`, 2048 байт | Загрузчик копирует банк; поезд заменяет face-ID клеток `$DA..$E1` | Текущий эпизод. |
| `CellTypeByIndex` | `$FFA4EA..$FFA5E9`, 256 байт | Загрузчик копирует банк | Текущий эпизод и обратная индексация. |
| `VisibleMapWindow` | `$FFA5FA..$FFA9F9`, 1024 байта | Окно 32×32 пересобирается при сдвиге локальной области | Видимый фрагмент карт этажей переменного размера; изменения отдельных клеток коммитятся обратно. |
| `TextureAnimationRecords` | база `$FFA9FC`; следующая область `$FFB9FC`, **не доказанная полезная длина** | Загрузчик копирует записи переменной длины до нулевого слова | Скрипт анимации эпизода; физический остаток нельзя объявлять свободным или автоматически пригодным для расширения. |
| `EpisodeMapCells` | `$FFB9FC..$FFF9FB`, арена 16 384 байта | `LoadEpisodeGeometry` `$0972A0..$0972CA` копирует активные этажи по их ширине × высоте | Изменяемые карты эпизода. Занятый префикс зависит от геометрии; остальная арена не доказана свободной для общего выделения. |

Основной порядок игрового прохода: сначала flush предыдущей DMA-очереди,
затем ввод, движение, `UpdateActors`, трассировка/отрисовка, наложения и
финальная постановка SAT-DMA. Оружие внутри наложений вызывается **после**
`UpdateActors`, поэтому созданный им снаряд обычно обновится на следующем
проходе. `VBlankInterrupt` меняет отдельные поля вне линейной последовательности;
меню и пауза имеют собственные пути сборки кадра.

Для расширения ROM ни один промежуток между строками таблицы не объявлен
свободной RAM. Особо опасны: предполагаемый запас SAT/DMA без проверки
границ; хвост анимационных записей; временная область словаря распаковщика;
неочищаемые байты повторно выделенного актёра; RAM у вершины адресного
пространства рядом со стеком. Перед переиспользованием участка надо найти
всех прямых и косвенных писателей, проверить возможное пересечение времени
жизни (включая VBlank и экраны UI), затем добавить проверку вместимости или
переместить область вместе со всеми указателями.
