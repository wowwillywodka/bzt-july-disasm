# Косвенная RAM: актёры и таблицы эпизода

Это статический проход по июльскому BZT. У игровых процедур `A6=$FF8000`;
`A0/A1/A3` требуют отдельного установления происхождения. Проверка
воспроизводится командой `make audit-indexed-ram`; отчёт в приватном проекте —
`metadata/indexed_ram_audit.json`.

## Массив актёров

`ActorPool` занимает `$FF123A..$FF2839`: **64 записи по `$58` байт**. Игрок
представлен отдельным `$58`-байтовым proxy `$FF11E2`, который не входит в пул.
Аллокатор находит свободный слот, прибавляя к указателю `ActorSize`, а обходы
живых актёров переходят по четырёхбайтовому `ActorNext` в начале каждого слота.

В проверенных областях, где тип `A0/A1/A3` установлен как указатель на актёра,
**нет индексных обращений** вида `(An,Dn)`. Есть 27 инструкций с косвенным
обращением к началу слота; все они относятся к `ActorNext` (чтение, сохранение,
перестройка списка или обнуление). Среди них аллокатор `$01C0BC/$01C0BE`,
обновление `$01BE56`, рисование `$01BF44`, поиск link-актёра `$020688` и
удаление `$01C15A..$01C17A`. В исходнике оставлено `(a0)/(a1)`:
`ActorNext(a0)` потребовало бы дополнительного слова смещения в коде 68000.
Именно поэтому отсутствие имени в этом операнде **не** означает неизвестное поле.

Границы типизированных областей берутся из `tools/actor_spec.py`. Этот результат
не доказывает тип каждого `An` во всём ROM и не исключает непрямую запись через
указатель, ранее сохранённый в другом регистре. Неизвестные поля `$0E/$35/$45`
не объявлены свободными; их состояние описано в [структуре актёра](ACTOR_STRUCTURE.md).

## Таблицы клеток и текстур в RAM

| Таблица | Адрес | Размер | Индекс / запись |
| --- | --- | ---: | --- |
| `CellIndexByType` | `$FF8BEA` | `$100` | `type` (byte) → первый сырой индекс клетки или 0 |
| `TextureDefinitions` | `$FF8CEA` | `$1000` | 256 записей по `$10` байт |
| `TextureOrder` | `$FF9CEA` | `$800` | 256 клеток по 8 байт: четыре word-ID текстур |
| `CellTypeByIndex` | `$FFA4EA` | `$100` | сырой индекс клетки (byte) → тип |

Три последние таблицы загрузчик копирует из выбранного банка эпизода в
`$0971BC..$0971E2`; обратную таблицу он строит в `$0971FE..$09721A`.
Для **каждого** значения типа `$00..$FF` первый совпадающий индекс ищется
по `CellTypeByIndex`; отсутствие совпадения даёт ноль. Поэтому новый тип
клетки нельзя считать безопасным только потому, что его код свободен:
потребители `CellIndexByType[type]` могут записать индекс 0 в карту.

Позднейшие писатели таблиц важны для ромхака:

- `AnimateWorldTextures` (`$0022D6`) пишет word в
  `TextureDefinitions + offset` из анимационного скрипта. Статические
  записи штатных банков проверены [аудитом стен](WALL_GRAPHICS.md), но этот
  проход не доказывает допустимость произвольного нового скрипта.
- `ApplyTrainTextureStrip` (`$098324..$0983DA`) переписывает четыре face-ID
  каждой из клеток `$DA..$E1` в `TextureOrder`. Последний записанный байт
  находится перед смещением `$710`, внутри таблицы размера `$800`.
- `RefreshFloorLabelAndColorMode` (`$00C018..$00C05E`) меняет слова
  `TextureDefinitions + $140/+0,+4,+8`, то есть запись 20. Это наложение
  текстовой метки этажа на обычный массив описаний текстур.

Размеры и индекс поезда теперь названы в `include/geometry_tables.inc`; эта
замена выражений не изменила ни одного байта ROM. Аудит фиксирует 22 исходные
инструкции-свидетеля, геометрию таблиц и набор косвенных ссылок `ActorNext`.
Остальные индексные обращения к RAM и полные диапазоны значений индексов во
всех игровых состояниях пока не охвачены.
