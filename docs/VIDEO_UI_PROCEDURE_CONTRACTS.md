# Границы видео и UI: загрузчики, продолжения и сохранённые экраны

Контракты ниже выведены из инструкций июльского ROM и прямых вызовов. Название операции не означает доказанной достижимости в обычной игре. В частности, последовательность `$021702` начинается в сохранённом экранном коде.

| Вход | Контракт и граница |
| --- | --- |
| [`FadeScreenThroughBlackPalette`](../src/video/fadescreenthroughblackpalette_001cba.asm) `$001CBA` | Ставит источник `BlackFadePalette`, ждёт VBlank, при нулевом флаге пишет 32 long из RAM-палитры в CRAM и вызывает `StepPaletteFade`, пока статус не станет 2. Пишет VDP напрямую; это цикл, а не разовая запись. |
| [`WriteTilemapColumnsVdpAddress`](../src/video/writetilemapcolumnsvdpaddress_002132.asm) `$002132` | **Продолжение** `UploadTilemapColumns`: единственная запись подготовленной команды в `VDP_CONTROL`. Самостоятельного `RTS` и собственного входного контракта нет. |
| [`WriteTilemapColumnWords`](../src/video/writetilemapcolumnwords_002138.asm) `$002138` | Следующее **продолжение**: восстанавливает `D0/D1`, читает слова `(A1)+`, прибавляет `D4`, пишет `VDP_DATA`; два `DBRA` возвращают цикл к `UploadTilemapColumns`. Ожидает ранее подготовленный стек и счётчики. |
| [`UploadInventorySlotIconsToVram`](../src/video/uploadinventorysloticonstovram_01173a.asm) `$01173A` | Ждёт окончания VBlank-передачи, задаёт VRAM-команду и четыре раза вызывает следующий обработчик для 4-байтных слотов инвентаря. |
| [`UploadInventorySlotIconToVram`](../src/video/uploadinventorysloticontovram_01175e.asm) `$01175E` | `A0` указывает на слот. Нулевой ID заливает 128 long нулями; иначе адресует `InventoryIconPointers`, пишет 26 long начала значка, выводит числовой счётчик и ещё 96 long. Значение ID должно оставаться в допустимом диапазоне таблицы. |
| [`ClearVideoAndSetScrollMinus16`](../src/video/clearvideoandsetscrollminus16_02176c.asm) `$02176C` | Вызывает очистку CRAM/VRAM и пишет значение −16 через `WriteVerticalScrollToVsram`. Не загружает сам экран. |
| [`WriteVerticalScrollToVsram`](../src/video/writeverticalscrolltovsram_021e4a.asm) `$021E4A` | Принимает `D0.w`, пишет VDP-команду `$40000010` и значение в `VDP_DATA`. Вызывается также меню персонажа, статистикой и сохранённым брифингом. |
| [`FadeFullPaletteToBlack`](../src/video/fadefullpalettetoblack_022018.asm) `$022018` | Ставит `D0=0`, `D5=$3F` и переходит в `FadePaletteToBlack`; это обёртка всего диапазона из 64 цветов, а не собственный цикл. |
| [`ClearCharacterMenuTilemapRegion`](../src/video/clearcharactermenutilemapregion_07b4fe.asm) `$07B4FE` | Вызывается после прокрутки меню персонажа. Выбирает смещение по `$FF2A4C`, вычисляет VDP-адрес через `CalculateTilemapAddress` и заполняет `$800` слов нулями. В альтернативной ветке часть входных регистров берётся у вызывающего кода; произвольный вызов без его контекста не обещан. |

[`InitializeRetainedScreenVideo`](../src/ui/initializeretainedscreenvideo_021728.asm) очищает CRAM/VRAM и вызывает `InitializeMenuVdp`; [`RunRetainedScreenPresentation`](../src/ui/runretainedscreenpresentation_021746.asm) повторно очищает видео, запускает большой сценарий [`$021784`](../src/ui/playretainedscreenpagesequence_021784.asm), ждёт `$78` кадров и вызывает fade. Оба вызываются из [`RetainedScreenSequence`](../src/ui/retainedscreensequence_021702.asm). Сценарий `$021784` назван по постраничному выводу; смысл каждой отдельной страницы и достижимость всего сохранённого экрана ещё не доказаны.

[`InitializeTitleScrollBackground`](../src/ui/initializetitlescrollbackground_022eb4.asm) сбрасывает счётчики и указатели скриптов заголовка, очищает участок VRAM. [`AdvanceTitleScrollBackground`](../src/ui/advancetitlescrollbackground_022f38.asm) уменьшает два таймера, продвигает указатели скриптов и выбирает строки `TitleAnimationCurves`. **Заголовочный цикл `$022980` вызывает эти два входа**, а не наоборот; один вызов `$022F38` не выполняет всю анимацию.

[`HandleVisibleObjectiveCellRenderState`](../src/renderer/handlevisibleobjectivecellrenderstate_008df6.asm) сохраняет указатель клетки, вызывает `CountAndClearObjectiveCellRenderState` и ставит `D3=1`. Это обработчик таблицы видимых клеток с побочным эффектом счётчика целей, а не построитель профиля высоты. [`RenderRetainedMapGrid`](../src/renderer/renderretainedmapgrid_00f35a.asm) строит сохранённую карту через `CellTypeByIndex`, но обычный вход в остров после раннего `RTS` не установлен. [`AppendVisibleActorsToSat`](../src/renderer/appendvisibleactorstosat_00f6b0.asm) обходит список активных актёров и добавляет видимые аппаратные спрайты в RAM-SAT; это отдельный путь от программной отрисовки 3D-спрайтов.

Два прежних `RendererRoutine` перенесены в link: [`QueueActorLinkCommand0F`](../src/link/queueactorlinkcommand0f_01f822.asm) и [`SetActorLinkCallbackAndQueueCommand12`](../src/link/setactorlinkcallbackandqueuecommand12_01f8a4.asm) вызывают `QueueLinkCommand`. Фрагмент `$01F844` после безусловного `JMP` **отделён** в [`SelectActorStateCounterParityFrame`](../src/actors/selectactorstatecounterparityframe_01f844.asm): он выбирает `D2=0/1` по младшему биту `ActorStateCounter` и переходит к `DrawActorAnimation`. Это настоящий общий вход из путей актёров, а не продолжение отправки link-пакета.
