# Положительные смещения A6 в июльском BZT

В игровом коде `A6 = $FF8000` (установка в `InitializeMachine` и
`InitializeHardware`). До этого прохода оставалось 18 числовых обращений к
девяти положительным смещениям. Адреса ниже вычислены как `$FF8000 + offset`;
они лежат **внутри уже известных массивов**, а не выделяют новые области RAM.

| Адрес | Новое имя | Основание |
| --- | --- | --- |
| `$FF8004` | `FrameBufferWordAtFF8004` | слово внутри `SoftwareFrameBuffer`; `CheckSceneExitAndPlayerDeath` читает его при обходе списка актёров. Оригинальная инструкция использует `A6`, а не `A0`, поэтому это **не** `ActorFlags`. |
| `$FF8025` | `FrameBufferByteAtFF8025` | байт внутри того же буфера; оставленная в ROM процедура `RetainedActorTargetTracking` читает и ограничивает его до `$20`/`$E0`. |
| `$FF8027` | `FrameBufferByteAtFF8027` | соседний байт буфера в той же процедуре. Обычная достижимость процедуры не доказана. |
| `$FF8ACA` | `CenterScreenColumnDepthWord` | `ScreenColumnDepthWords + $80`, то есть слово колонки 64. Прицеливание сравнивает с ним обратную глубину; лазер использует его как базу индексирования. |
| `$FF8B9A` | `SceneBackgroundColumn1` | `SceneBackgroundColumns + $50`, начало второй 80-байтовой фоновой колонки; используется веткой отрицательного смещения фона. |
| `$FF8C16` | `CellIndexForType2C` | `CellIndexByType[$2C]`; байт ставится в карту при заполнении пустой клетки. |
| `$FF8C17` | `CellIndexForType2D` | `CellIndexByType[$2D]`; байт ставится в карту путями изменения стены. |
| `$FF8C18` | `CellIndexForType2E` | `CellIndexByType[$2E]`; аналогичный вариант изменения стены. |
| `$FF8E2A` | `FloorLabelTextureDefinition` | `TextureDefinitions + $140`, запись 20 размером 16 байт. `RefreshFloorLabelAndColorMode` записывает в неё три слова для метки этажа. |

В GEMS по адресам ROM `$07A000..$07AE75` `A6` — указатель кадра стека
драйвера. Его 14 обращений `$8/$C/$10/$14(a6)` сохранены как смещения
аргументов; считать их адресами игровой RAM было бы ошибкой.

`tools/audit_ram.py` теперь проверяет отсутствие числовых положительных A6 в
игровом коде и 18 исходных инструкций-свидетелей. Этот проход не раскрывает
все косвенные и индексные обращения к памяти и не доказывает достижимость
оставленной процедуры слежения.
