# Передача координат и временных полей между игровым кодом и рендером

Границы программного кадра, глубин и фоновых колонок:
[RENDER_BUFFER_BOUNDS.md](RENDER_BUFFER_BOUNDS.md).

Июльский BZT. Адреса ниже — RAM 68000, A6 в этих процедурах равен `$FF8000`.
Это контракт по записям и чтениям в исходном июльском ROM; он не утверждает,
что так же устроены другие сборки.

## Центр карты и аппаратные спрайты

`ClampPlayerToFloorBoundsAndRenderWorld` (`$00F216`) читает `PlayerX/Y`
и записывает `MapSpriteViewCenterX/Y` (`$FF0DF6/$FF0DF8`). Целая часть
каждой координаты ограничивается снизу 5 клетками. Верхний предел — 27
клеток при размере этажа от 32, иначе `размер − 5` клеток. Младший байт
координаты игрока сохраняется даже при ограничении. Сами `PlayerX/Y` эта
процедура не меняет. После ожидания завершения фаз VBlank она передаёт
управление в `RenderRetainedMapGrid`.

`RenderRetainedMapGrid` вычитает 5 из целой части центра для начала видимого
участка карты. `AppendPlayerWorldSpritesToSat` использует этот же центр
для расположения игровых SAT-спрайтов, а `AppendVisibleActorsToSat`
сравнивает координаты актёров с центром в пределах `$500` по обеим осям.
Поэтому это общая опора **двумерной карты и SAT**, а не изменённые координаты
игрока и не перспективная камера.

## Дробная позиция для лучей

`TraceAndDrawVisibleWorld` (`$00C1C6`) вычисляет по каждой оси пару:

```text
PlayerCellFractionX/Y           = PlayerX/Y & $FF
PlayerCellFractionX/YComplement = $FF - (PlayerX/Y & $FF)
```

Это слова `$FF0E1C/$FF0E1E` и `$FF0E18/$FF0E1A` соответственно.
Дальнейшие обходчики лучей читают обе части пары при выборе расстояния
до следующей границы клетки. Сохранённый вход
`UpdatePlayerCellCoordinates` (`$0974FA`) записывает те же значения;
его достижимость из штатного игрового цикла отдельно не доказана.

## Временные слова программного спрайта

`ScaleAndDrawSoftwareSpriteTile` (`$00F8BC`) получает геометрию в регистрах,
затем заполняет временные слова `$FF10D0..$FF10DA`. Они общие для вызовов
рендера: это не свойства конкретного актёра и их нельзя сохранять между
рисованием двух спрайтов.

| Адрес | Имя | Запись и использование |
|---|---|---|
| `$FF10D0` | `SoftwareSpriteSourceColumnStride` | +32 для прямого обхода упакованных исходных столбцов; −32 после зеркального сдвига указателя A1. |
| `$FF10D2` | `LargeSpriteVerticalSourceStep` | Младшее слово частного `$200000 / высота`; шаг дробной фазы исходной строки при проекции выше 80 пикселей. |
| `$FF10D4` | `LargeSpriteVerticalSourcePhase` | Начальная дробная фаза; при отрицательной верхней координате учитывает уже отсечённые строки. |
| `$FF10D6` | `LargeSpriteColumnLastRow` | Число видимых строк минус один для `DBRA` в `DrawLargeSpriteColumn`. |
| `$FF10D8` | `SoftwareSpriteUnclippedTopY` | Исходная верхняя координата до обрезки; нужна для смещения A1 в высокой ветви. |
| `$FF10DA` | `SoftwareSpriteProjectionScale` | Масштаб из draw callback; сравнение с глубиной столбца и выбор цветового ремапа. |

При высоте не больше `$50` рендер берёт адрес одного из коротких
столбцовых обработчиков из `SpriteColumnEntryPointers`. При большей высоте
использует `DrawLargeSpriteColumn` (`$00FC18`), который читает фазу и
последнюю строку из RAM, а шаг получает в D2. При отсутствии зеркала шаг
между исходными столбцами равен +32; при зеркале −32. Слово масштаба
записывают несколько обработчиков объектов и снарядов перед общим вызовом
скейлера. Сам скейлер не вычисляет перспективный масштаб заново.

Порядок чтений и отсечения виден в исходниках
[скейлера](../src/renderer/scaleanddrawsoftwarespritetile_00f8bc.asm) и
[высокого столбца](../src/renderer/drawlargespritecolumn_00fc18.asm).
