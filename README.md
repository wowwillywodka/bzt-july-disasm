# Beyond Zero Tolerance — July prototype disassembly

Этот репозиторий не содержит исходный ROM, графику, карты, палитры, текст,
звуковые банки, PCM-сэмплы и прочие ROM-зависимые данные. Они извлекаются
локально из принадлежащей пользователю июльской версии прототипа.

Ожидаемый ROM имеет размер `3 145 728` байт и SHA-256:

```text
8f0af150b642e1e190566a96d19732695164d926244764407560949cee02d8b0
```

## Охват разбора

**Структурный охват ROM — 100%.** Все 3 145 728 байт находятся в 1378
последовательных блоках; выделенное тело 68000-кода декодировано и собирается
обратно без изменения образа. Это не означает, что смысл каждого ресурса или
каждая игровая ветвь уже полностью исследованы.

После `make extract` и сборки проект создаёт **побайтно идентичный исходному
образ**: 3 145 728 байт, SHA-256
`8f0af150b642e1e190566a96d19732695164d926244764407560949cee02d8b0`.
Команда `make verify ROM="…"` дополнительно сравнивает его с ROM пользователя
и сообщает число различающихся байтов.

Таблица показывает долю размеченных точек входа с содержательным именем
среди всех размеченных точек каждой подсистемы. В неё входят проверенные
локальные имена, роли актёров и точные совпадения с ZT;
временных имён вида `RendererRoutine_…` больше нет. Это охват имён
размеченных входов, а не процент понимания всего кода и данных. Подробности и

После сборки команда `python3 tools/export_sound_events.py` создаёт
`build/sound_events.csv` с 133 записями таблицы GEMS. Файл создаётся локально
из ROM пользователя и не входит в публикуемый исходник. Покрытие имён звуковых
процедур не означает, что каждому ID уже сопоставлено слышимое звучание.

Графика и палитры не входят в эту метрику: это ресурсные банки, а не наборы
точек входа. Они целиком отделены от кода и описаны в карте ROM, однако степень
понимания внутреннего формата у разных банков различается.

## С нуля

Нужны Python 3 и VASM для `m68k/mot` и `z80/oldstyle`.

```sh
git clone https://github.com/wowwillywodka/bzt-july-disasm.git bztjuly-public
cd bztjuly-public
make extract ROM="/путь/к/Beyond Zero Tolerance (Prototype).bin"
make check
make verify ROM="/путь/к/Beyond Zero Tolerance (Prototype).bin"
```

`extract` создаёт игнорируемую папку `generated/data`; ROM не копируется в
репозиторий. `check` сверяет собранный образ с зафиксированным размером и
SHA-256. `verify` дополнительно делает побайтное сравнение с указанным ROM.

На Windows эти же шаги можно выполнить без `make`:

```powershell
py -3 tools\extract_rom.py --rom "C:\путь\Beyond Zero Tolerance (Prototype).bin"
py -3 tools\build.py
py -3 tools\verify.py --reference "C:\путь\Beyond Zero Tolerance (Prototype).bin"
```

Скрипт `tools/build.py` ищет VASM через переменные `VASM_M68K` и `VASM_Z80`,
затем в `.tools/vasm`. Если инструментов нет, он может скачать закреплённую
ревизию VASM и собрать её; для этого нужны Git и Make. На Windows удобно
указать пути к `vasmm68k_mot.exe` и `vasmz80_oldstyle.exe` через эти две
переменные.

## Проверка публикационной копии

Перед публикацией чистого дерева выполните:

```sh
make audit-release
```

Аудит проверяет, что в публикуемых файлах нет ROM-блоков: каждый ресурсный
исходник является только заглушкой с `incbin generated/data/...`, а исходные
ROM, `assets`, галереи и бинарные файлы отсутствуют.

`generated/`, `build/` и `.tools/` перечислены в `.gitignore`; не добавляйте
их в Git принудительно.
